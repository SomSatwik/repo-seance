# GhostTrace CLI

Installable terminal companion for the Repo Séance API. Reuses the existing
`/ws/ghosttrace` WebSocket endpoint — no safety engine or Gemma logic is
reimplemented here.

## Prerequisites

- Python 3.8 or newer.
- The Repo Séance API running with `GHOSTTRACE_ENABLED=true`. Follow the
  database and API setup steps in the repository's [README](../../README.md).
- Ollama is optional; the API returns a deterministic fallback explanation if
  Gemma is unavailable.

Set `GHOSTTRACE_ENABLED=true` in the API's `.env`, then start the backend from
`apps/api`:

```powershell
uvicorn main:app --reload --port 8000
```

## Install

From the `repo-seance` root:

```powershell
pip install -e packages/ghosttrace-cli
```

This registers the `ghosttrace` command on your PATH.

To verify the installed entry point in a new PowerShell window:

```powershell
Get-Command ghosttrace
ghosttrace --help
```

## Run

Import a repository first. The root repository's
[demo script](../../docs/demo-script.md#2-import-a-fresh-real-repository)
shows the PowerShell commands that import it, wait for ingestion, and set
`$repoId` to the returned ID. In that same PowerShell window, run:

```powershell
ghosttrace --repo $repoId
```

Type commands to classify and `exit` to quit. `Ctrl+C` also exits cleanly.
The CLI sends each command to the backend over WebSocket; classifications
remain deterministic and explanations are generated by the same API used by
the web terminal.

Options:

| Flag | Env var | Default | Meaning |
|------|---------|---------|---------|
| `--api-url` | `GHOSTTRACE_API_URL` | `ws://localhost:8000` | Backend WebSocket URL |
| `--repo` | `GHOSTTRACE_REPO_ID` | Required | Repository id to classify against; use the id returned by ingestion |

Example:

```powershell
ghosttrace --repo $repoId
```

Then type a shell command at the `>` prompt:

```
> ls -la
  [SAFE]
  command: ls -la
  ...

> rm -rf ./build
  [DESTRUCTIVE]
  command: rm -rf ./build
  rules: rm with recursive + force (rm -rf), ...
  The command `rm -rf ./build` is **DESTRUCTIVE**. ...
  context: commit:60186a9a, ...
```

## Why both a web terminal and CLI?

The web terminal (`apps/web/app/ghosttrace/`) is the demo and preview surface:
it presents GhostTrace's horror identity in a browser. The CLI is the
installable product surface: a real command in the user's terminal. Both use
the exact same backend WebSocket, deterministic safety engine, and grounded
explanations, with no duplicated safety logic.

The CLI uses ANSI styling for its warning hierarchy and initializes Colorama
for Windows terminal compatibility. Destructive results get a brief red ASCII
warning mark; caution and destructive results include one restrained rotating
aside, while safe results stay understated.
